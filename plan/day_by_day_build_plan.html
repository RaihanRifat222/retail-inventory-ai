Week 1 — foundation
1
Environment + data loaded into Postgres Setup
Install Python deps, spin up PostgreSQL locally, write a single script that reads all 3 H&M CSVs and loads them into your database.
✓ Done when: you can run a SQL query and see real H&M data come back
2
Synthetic data layer Setup
Enrich the raw H&M data with the missing columns — sizes, cost prices, stock snapshots, 3 fictional stores. This becomes your demo dataset.
✓ Done when: every product has a size, a stock level, and belongs to a store
3
FastAPI backend skeleton Setup
Stand up FastAPI, connect it to Postgres via SQLAlchemy, and build 3–4 basic endpoints: list products, get stock by SKU, get sales by date range.
✓ Done when: you can hit your API in the browser and get real data back
Week 2 — AI features
4
Demand forecasting model AI
Train a Prophet model on the H&M transaction history. Generate 30/60/90-day forecasts per product category. Expose it as a FastAPI endpoint.
✓ Done when: /forecast?product_id=X returns a predicted demand curve
5
Loss prevention — anomaly detection AI
Inject synthetic shrinkage events into your data, then train an Isolation Forest model to detect stock anomalies. Expose flagged anomalies via API.
✓ Done when: /anomalies returns a ranked list of suspicious stock deltas
6
Auto-replenishment engine AI
Use the forecast output to compute dynamic reorder points. Auto-generate purchase order drafts when stock falls below threshold.
✓ Done when: /replenishment returns a list of SKUs that need reordering + suggested quantities
Week 3 — dashboard
7
React app scaffold Frontend
Create the Vite + React + Tailwind project, install shadcn/ui and TanStack Query, wire it up to your FastAPI backend, build a basic nav shell.
✓ Done when: the app loads and a sidebar shows your 3 main sections
8
Analytics dashboard page Frontend
Build the main dashboard: sell-through bar chart, demand forecast line chart, top SKUs table. All pulling live data from your API.
✓ Done when: the dashboard shows real H&M data in charts
9
Loss prevention + replenishment pages Frontend
Build the anomaly alerts table (flagged SKUs with severity scores) and the replenishment queue (SKUs needing reorder + approve/dismiss actions).
✓ Done when: both pages load with real data and you can interact with them
Week 4 — polish + demo ready
10
Natural language query (Claude API) Polish
Add the "ask your inventory" feature — a text input that sends questions to Claude, which translates them into SQL queries and returns results as charts.
✓ Done when: you can type "which items underperformed last month?" and get a chart back
11
Deploy to Railway Polish
Deploy FastAPI backend + PostgreSQL + React frontend to Railway. Get a live URL you can share with anyone — this is your portfolio link.
✓ Done when: the app is live at a public URL
12
Demo polish + README Polish
Seed the database with compelling demo scenarios (a stockout, a spike, a flagged theft). Write the README and GitHub description. Done.
✓ Done when: you'd be happy sending the GitHub link to a hiring manager
